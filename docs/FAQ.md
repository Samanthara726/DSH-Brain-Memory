# FAQ / 排查

---

## 启动

**Q：`python server/memory_service.py` 报 `SyntaxError: invalid non-printable character U+FEFF`？**
文件被存成了带 BOM 的 UTF-8。用编辑器另存为「UTF-8（无 BOM）」。

**Q：端口被占用？**
`MEM_PORT=8791 python server/memory_service.py` 换一个，记得调用方也跟着改。

**Q：服务起来了但 `/stats` 一直 `total: 0`？**
还没写过东西。先跑一遍 `examples/curl.sh`。

**Q：能让它开机自启吗？**
服务是单文件 `http.server`，Linux 用 systemd、Windows 用计划任务/nssm，套一层就行（本机是这么干的）。不建议用 `nohup &`——挂了没人拉起来。

## 写入

**Q：写了但没感觉库变大？**
`sha256` 去重：完全相同的一段话只加固不新增。差一个字都算新的。

**Q：`/write` 返回 `dedup: true` 是什么？**
已经存在，`importance` 轻微 +0.03，正文不覆盖。

**Q：能存很长的文本吗？**
单条 4000 字上限，超出截断并标注。一坨几十条消息压成一条，召回反而差——分段写。

**Q：`pin: true` 用多了会怎样？**
永不衰减的条目越多，用户会「记得所有事」但注入依然只给 3 段，等于把真正相关的挤掉。**钉住只给明确指令**（「记住这个」）。

## 召回

**Q：`/context` 返回 `block: ""`？**
三种可能：
1. 库是空的；
2. 门槛太高（`MEM_MIN_SCORE` / `MEM_MIN_SIM`）；
3. 查询太长太散——2-gram 命中的比例被摊薄了。用更短、更具体的查询。

**Q：翻得到但不相关？**
先看返回里的 `sim` / `cos`。`sim` 低而 `cos` 高，说明是语义兜底那条被放进来了——`MEM_COS_FALLBACK` 调高一点。

**Q：向量服务没起，会影响什么？**
只少了语义那一路。`/stats` 里 `embed_enabled: true` 但 `vectors: 0` 就是没补过向量，跑一次 `/reindex`。

**Q：`/recall` 和 `/context` 为什么结果不一样？**
设计如此。`/context` 是自动注入（精确优先，宁漏不错），`/recall` 是手动翻旧账（语义候选也进来）。见 [说明书 §5](说明书.md)。

**Q：`reindex` 报 `timed out`？**
别一次补太多。`{"limit":24}` 一批，循环几轮。

## 遗忘

**Q：`importance` 怎么自己变了？**
每天跑一次 FSRS-5 衰减：`importance = base × R`。这是设计，不是 bug。

**Q：`pinned: 13` 是什么意思？**
重要度 ≥ 0.7 或显式 `pin` 的条目，永不衰减。这个数字突然变大，说明你的写入逻辑给的 `importance` 太高了。

**Q：`frozen` 一直涨？**
掉到冻结线以下的记忆不再自动注入。想看它们回不回来：`/recall` 手动翻一次，`R` 就回到 1。

**Q：能物理删除吗？**
服务没有删除接口（故意不提供）。真要删：`sqlite3 state/memory/memory.db "UPDATE documents SET deleted=1 WHERE id=..."`。
软删除的条目不再参与检索，但正文还在库里。

## 面板

**Q：面板打不开 / 一片黑？**
先看 `curl 127.0.0.1:8643/api/graph` 能不能返回节点。报「记忆服务 /graph 返回 …」就是记忆服务没起，或者 `MEM_BASE` 指错了。

**Q：节点少了一大截？**
`/graph` 最多返回 800 条（按 important 排序）。库大了之后面板只显示最重要的那部分。

**Q：点了「插件」「总线」之类的按钮报错？**
面板原本来自另一个插件生态，那些入口跟本项目无关，适配层一律返回 403。不影响查看记忆。

**Q：为什么不会自动刷新？**
故意的。每秒重绘一遍既看不到内容也白烧 CPU，需要最新数据点「⟳ 重新加载」。

## 隐私与安全

**Q：库能公开吗？**
不能。里面有对话原文。`state/` 已经在 `.gitignore` 里，但发布截图/备份前自己再检查一遍。

**Q：服务要暴露到公网吗？**
不要。它没有任何鉴权，只监听 `127.0.0.1` 是设计的一部分。要在别的机器上用，自己套一层反代 + 鉴权。

**Q：会调外部 API 吗？**
不会。唯一的外部依赖是**本机**的 embed 服务（默认 8794），模型全部读本地文件。

## 和别的方案比

**Q：为什么不用 LangChain / LlamaIndex 的记忆模块？**
它们大多绑死「向量检索 + 摘要」，没有「遗忘曲线」，也没解决中文小模型在长片段上分不清真假的问题。这套更小、更透明，所有逻辑都在两个文件里。

**Q：为什么不存成 markdown？**
可以，但召回会变成全文扫描 + 手写匹配。SQLite 带 2-gram 指纹和 FSRS 字段，几万条也不慢。

**Q：能换成 PostgreSQL / MySQL 吗？**
逻辑上可以（`connect()` 换掉就行），但 `vectors` 那列的 BLOB + 全表扫在 SQLite 上反而更简单。没有明确收益。
